# F1-006.2 — подготовка DRAFT-кандидата обновления

Одна команда: `python tools/prepare_update.py --baseline private/f1db-all-f10033-reviewed.json --output private/updates/run-001`.

Перед запуском необходим существующий проверенный структурно F1DB-кандидат. Нижняя граница импорта определяется по его календарю, верхняя — по свежему архиву. Новые сезоны и результаты не требуют правки года в коде. Загрузка зависит от публикации нового релиза F1DB. Проверяются размер, SHA-256 и ZIP/CRC средствами fetch_f1db. Существующий кеш повторно проверяется; старый архив не изменяется.

Последовательность: fetch → import → reconcile → correct → check_update → audit → новый candidate.json. Серьёзные проблемы аудита, пропавшие идентификаторы/результаты, конфликты календаря и неожиданные исторические данные блокируют экспорт. Замечания countback остаются в отчёте и не блокируют локальный DRAFT; они не считаются устранёнными. Новый каталог обязателен; ранее созданные файлы не перезаписываются. Успешный запуск требует одновременно status=draft_ready, stage=complete и соответствия SHA-256 кандидата в update-report.json; само наличие candidate.json не является приёмкой. Никакой активации, публикации, изменения main, index23.html или localStorage. Сбой/прерывание может оставить неполный каталог диагностики; следующий запуск — в новый каталог.

Опционально `--user private/f1-user-backup.json` проверяет предоставленный JSON (схема v2 или экспорт оболочки браузера version=1 с bindings), но не изменяет его. Без файла нельзя утверждать, что реальные прогнозы проверены; код не имеет доступа к localStorage. Прогнозы не копируются в кандидат или публичный каталог.

Отчёты: import-report.json, historical-report.json, audit-report.json, update-report.json (статус, контрольные суммы, сведения о релизе, новые годы/этапы/сессии, изменившиеся даты, результаты и зачёты). При блокировке выводится UPDATE BLOCKED и записывается диагностический отчёт, если доступен выходной каталог.

Офлайн-воспроизведение: дополнительно `--release-json private/release.json --local-archive private/f1db/f1db-csv.zip --as-of YYYY-MM-DD`; метаданные должны соответствовать формату GitHub API, размеру и digest архива. Офлайн режим не является проверкой свежести релиза. Параметр --as-of запрещён в сетевом режиме. Утверждение независимой исторической сверки, безопасная активация, планировщик GitHub Actions и публикация остаются следующими задачами. Неизвестные изменения регламентов не должны автоматически считаться проверенными.
