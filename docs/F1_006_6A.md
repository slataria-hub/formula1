# F1-006.6A — точная DRAFT-сборка и блокировка публикации

## Принятые исходные данные
Пользователь подтвердил Actions #3 (commit 15b51a6, 2m41s), ветку f1-data b20306f677abd3c1b80b17aa0e8fa2141720cf0e, манифест version=1, officialSha256 9ce80d14bcc406f97f6a977a3cf005bf68878abf818eb52a40763190703a6807, v2026.21.0. Независимая верификация pending, publicationAuthorized=false. Реальное изменившееся обновление не испытано.

## Назначение
`tools/prepare_publication.py` читает постоянный DRAFT через Store.load, проверяет исходный манифест, сверяет ожидаемый commit/hash (если указаны), повторяет аудит, формирует отдельный пакет `site/` и `publication-report.json`. В site копируются ровно шесть штатных web-ресурсов, исходные байты official.json и SOURCE.txt с атрибуцией. В баннере интерфейса добавлена видимая атрибуция F1DB/CC BY 4.0. При `--code-commit` байты web-ресурсов сверяются с указанным HEAD. По окончании проверяются все хеши, размер, точный состав файлов, повторное чтение remote head. Рабочая база не изменяется. Пакет создаётся атомарно в новом private-каталоге; имеющийся каталог не перезаписывается.

`verify` проверяет целостность и согласованность пакета, но не является криптографической подписью/независимой приёмкой. Для связи с доверенным источником передавайте ожидаемые commit/hash; облачный workflow делает это автоматически. Все блокирующие условия обязательны; флаг publicationAuthorized всегда false, разрешение не может быть задано параметром. Никакого Pages deploy, смены ветки main или записи в f1-data в этом инструменте нет.

## Локальный запуск
Из корня проекта:
```
.\.venv\Scripts\python.exe tools/prepare_publication.py build --output private/publication-local-001
.\.venv\Scripts\python.exe tools/prepare_publication.py verify --bundle private/publication-local-001
```
Использовать новый каталог при повторном запуске. Для проверки привязки к подтверждённому remote передать `--expected-commit` и `--expected-sha`. Для просмотра: `python -m http.server 8765 --bind 127.0.0.1 --directory private/publication-local-001/site`. При прежнем origin браузерные прогнозы остаются локальными. Если сервер на 8765 уже запущен, остановить его перед запуском нового.

## Облако
Тот же workflow после успешного задания draft передаёт `afterCommit` и `officialSha256` из persistence.json отдельному read-only заданию site-rehearsal. Оно извлекает только эту версию f1-data (если ветка успела измениться, сборка блокируется), сверяет web-ресурсы с GITHUB_SHA, собирает и повторно проверяет пакет. Артефакт f1-draft-site-* — только для проверки, хранится 14 дней. Сами данные остаются в постоянной f1-data. Публичные артефакты и ветки не должны содержать личных данных. Расписание ещё не активно из feature-ветки. Не изменять main или настройки Pages.

## Оставшиеся блокировки
- Независимая историческая приёмка (включая 3 countback-кандидата и оставшиеся расхождения).
- Визуальная приёмка точного итогового дизайна и проверка браузерного импорта/переноса пользовательских данных между origin, если потребуется.
- Явное разрешение конкретной версии на публикацию.
- Деплой, постоянная история опубликованных версий и удалённый rollback; активация расписания на default branch после приёмки.

Это подэтап F1-006.6A, не завершённая автоматическая публикация. Следующие релизы F1DB остаются без ограничения года; новый регламент прогнозирования проверяется отдельно.
