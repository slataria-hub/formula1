# F1-006.5 — постоянное DRAFT-хранилище

Не публикует сайт. Ветка `f1-data` содержит только `official.json` (DRAFT)
и `manifest.json`. F1DB, CC BY 4.0, преобразованные данные. Если репозиторий
публичный, содержимое этой ветки также публично; для конфиденциального DRAFT
не выполняйте bootstrap в публичном репозитории. Прогнозы, браузерные
данные, исходный ZIP, архивы `private/` и файлы сайта в ветку не записываются.

## Инициализация (один раз, до push нового workflow)

Из корня проекта (PowerShell):

```powershell
.\.venv\Scripts\python.exe tools/persist_draft.py bootstrap --baseline private/managed-preview/site/official.json
.\.venv\Scripts\python.exe tools/persist_draft.py status
```

Используется уже настроенный Git `origin` и существующая авторизация Git.
Bootstrap сверяет спортивный хеш с закреплённым исходным релизом F1DB
v2026.21.0, повторяет аудит, создаёт отдельный корневой коммит. Не выполняет
checkout, не меняет текущую рабочую ветку. Повторный bootstrap запрещён.
Если `f1-data` уже существует, проверьте status; не удаляйте ветку для
обхода проверки. При иной исходной базе потребуется отдельное согласование.

## Обновление

Workflow F1 DRAFT update при push в feature-ветку выполняет тесты,
затем `tools/persist_draft.py update --output private/cloud-run`. Скрипт
читает точную вершину f1-data, проверяет хеши и структуру, готовит кандидата,
повторно проверяет его через managed activation, проверяет версию релиза
и сохраняет только проверенные спортивные изменения. При том же спортивном
содержимом ветка не изменяется (`no_change`). Поле release манифеста — релиз,
из которого сохранена текущая база, не обязательно последний проверенный
релиз без изменений. `observedRelease` фиксируется в отчёте прогона.
Новый коммит имеет ровно одного родителя — проверенную вершину f1-data.
Точная git lease (включая отсутствие ветки при bootstrap) защищает от гонки
записей, удаления ветки во время прогона и перезаписи чужого коммита;
безусловный force push не используется. Отсутствие ветки в обычном прогоне
блокирует обновление, автоматически исходный снимок не восстанавливается.

Права `contents: write` выданы job draft для записи ветки; GitHub не
ограничивает этот токен одной веткой, поэтому доверяйте коду этой ветки.
Токен передаётся переменной окружения на шаге обновления, git использует
его только для проверенного HTTPS origin, без сохранения credentials.
Нет прав Pages, нет checkout/изменения main, нет деплоя. Ошибка сети,
валидатора, аудита, совместимости или stale lease блокирует продвижение.
Если связь прервётся после успешного push, сначала проверяйте status.

Локальная проверка (необязательно; эта команда действительно может
записать новую проверенную DRAFT-версию в f1-data):

```powershell
.\.venv\Scripts\python.exe tools/persist_draft.py update --output private/persist-local-001
```

## Хранение и ограничения

Git-история сохраняет прошлые версии; 14 дней относятся только к Actions
artifacts. Проверка состояния: `persist_draft.py status`; просмотр истории:
`git fetch origin f1-data` и `git log --oneline FETCH_HEAD`. Не переписывать
историю и не удалять ветку. Ручной откат удалённой ветки пока не реализован;
локальный managed rollback остаётся доступен. Для отката публичного сайта
потребуется отдельный шлюз публикации с явно утверждённой версией.
Лимит размера JSON установлен 90 MiB, до лимита GitHub 100 MiB; при достижении
потребуется миграция хранения. Политика очистки истории не реализована.

Пока `main` неизменна, расписание GitHub не активно; реальный облачный
запуск с записью ветки требует проверки. Независимая историческая приёмка
и разрешение на публикацию всё ещё отсутствуют. Никаких пользовательских
данных не передавать в облако. Автоматическая загрузка будущих сезонов
без ежегодной правки года обязательна.
