# F1-006.1 — загрузчик стабильных релизов F1DB

Дата разработки: 2026-11-27. Статус: локальная приёмка; DRAFT; публикация не разрешена.

## Назначение

`tools/fetch_f1db.py` обращается к `https://api.github.com/repos/f1db/f1db/releases/latest` и выбирает `f1db-csv.zip` из стабильного опубликованного релиза. Год не фиксируется. Предварительные и черновые релизы не принимаются. Имя файла, версия, URL, размер и SHA-256 проверяются; отсутствие digest блокирует загрузку. GitHub API: https://docs.github.com/en/rest/releases/releases#get-the-latest-release; сведения об assets: https://docs.github.com/en/rest/releases/assets. F1DB: https://github.com/f1db/f1db (CC BY 4.0).

## Запуск в PowerShell

```powershell
.\.venv\Scripts\python.exe tools/fetch_f1db.py --metadata-only
.\.venv\Scripts\python.exe tools/fetch_f1db.py
.\.venv\Scripts\python.exe tools/fetch_f1db.py
```

Повторный запуск при неизменном релизе должен вывести CACHE. При появлении нового релиза скачивается отдельный архив. В конце выводится JSON с `tag`, `sha256`, `size`, `archive`, `result` и `publicationAuthorized: false`. Кеш по умолчанию: `private/f1db/releases/<tag>/<sha256>/f1db-csv.zip`. Исходный `private/f1db/f1db-csv.zip` и рабочая база не заменяются. Если кеш повреждён, операция блокируется; его нельзя молча перезаписывать. Временные файлы удаляются при ошибке. До трёх попыток на временный сетевой сбой; HTTP 429/403 не повторяются автоматически в рамках запуска. Тайм-аут по умолчанию 30 секунд на сетевую операцию; `--timeout 60` допустим. Параметр `--cache-dir` для отдельного тестового кеша.

## Автономная проверка

`--release-json <metadata.json> --local-archive <zip>` — режим локального тестирования с сохранёнными метаданными. Это не подтверждение текущего релиза GitHub. Не используется для автоматической публикации. В тестах проверен фактический архив v2026.21.0 (SHA-256 8c33f41f7e095e995634305a33b28bd8638366056f877109ffc290d06d341950), повторное использование кеша и ошибки. Реальное сетевое соединение из среды разработки не удалось (DNS api.github.com). Проверка на ПК необходима.

## Граница этапа

Загрузчик не импортирует данные, не меняет официальный JSON, localStorage, исходный HTML или GitHub Pages, не выполняет git push. Историческая приёмка не завершена. Следующие шаги: автоматический импорт найденного архива с `--from-season 2000` без верхнего года, исторические корректировки, аудит и проверка совместимости, отчёт о различиях, планировщик GitHub Actions сначала в режиме кандидата без публикации. Автоматическое получение нового календаря и результатов должно работать при переходе года без правки кода. При отказе источника или проверок сохраняется прежняя рабочая база. Не использовать предположения о правилах нового сезона в вероятностной модели; профиль FIA проверяется отдельно, загрузка результатов не блокируется отсутствием профиля прогнозирования. Реальные пользовательские прогнозы сохраняются отдельно, legacy-тестовый прогноз не переносится.
