## Automatic updates (mandatory, stage 03)

New archives use the existing open-ended `--from-season 2000` command. Events now also store `externalEventId` and `grandPrixKey` from F1DB; internal round-based IDs are retained for compatibility. `check_update.py` rejects removed IDs/aliases, changed provider event identity, lost sessions/participants/standings/adjustments, and regressions of completed events. Old datasets without external IDs use conservative name/circuit comparison. Dates may change for the same event; changed round assignment is blocked pending explicit migration, not silently reassigned. Optional `--user` checks a v2 user file against the candidate without editing it; no legacy migration or publication is performed. This is a compatibility gate, not a full reconciliation or release authorization. Schedule/download/atomic deployment/rollback and historical result-diff policy still need implementation; future archive changes must be checked and approved before publication. Stable event key migration is required before automatically accepting renumbered calendars. Preserve existing predictions, no year hardcoding.
