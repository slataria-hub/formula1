# F1-002B — офлайн-импорт F1DB

## Использование
Из корня проекта (PowerShell):

```powershell
.\.venv\Scripts\python.exe tools/import_f1db.py --archive private/f1db/f1db-csv.zip --season 2000 --output private/f1db-2000.json --report private/f1db-2000-report.json
.\.venv\Scripts\python.exe tools/validate_data.py private/f1db-2000.json
```

Для диапазона используйте `--from-season 2000 --to-season 2026`. Если верхний предел не указан, импортер обнаруживает максимальный год в календаре входного архива. По умолчанию начальный год 2000. Это не сетевой загрузчик; используйте новый архив для следующего обновления. Выходные файлы должны отсутствовать. Импортер не перезаписывает существующие файлы, включая пользовательские данные, и не публикует результат. Для повторного прогона укажите новое имя. Создание каждого выходного файла атомарно на поддерживающей hard links файловой системе (NTFS); отчёт и кандидат не являются единой файловой транзакцией. Все кандидаты имеют статус draft. Для воспроизводимости используйте `--as-of YYYY-MM-DD`; по умолчанию дата UTC запуска.

## Контракт и происхождение
- Архив проверяется CRC; SHA-256 сохраняется в sources. Для проверенного архива v2026.21.0 ревизия определяется по хешу; для другого релиза можно передать `--revision`. `retrievedAt` — локальное время изменения файла архива (приближение времени получения), не дата выпуска. Не выдавать этот timestamp за подтверждённое время скачивания.
- F1DB: https://github.com/f1db/f1db ; лицензия данных CC BY 4.0, https://creativecommons.org/licenses/by/4.0/ . Перед публикацией необходима атрибуция и обозначение преобразований. Исходный архив хранить отдельно.
- Первичные ID кандидата `f1db:<id>`; уже существующие `jolpica:<id>` не заменяются в принятых данных и пользовательских прогнозах. До перехода к единой базе обязателен проверенный crosswalk идентификаторов и миграция ссылок пользователя. Сезон/этап сохраняют прежний формат; перенумерация календаря требует проверки, а не слепой перезаписи.
- Загружаются календарь, гонки, квалификации, спринты, спринт-квалификации, снимки зачётов после этапов и лучший круг гонки. Победы в снимках вычисляются по гоночным победителям (не спринтам). Для гонок/спринтов пустое поле начисленных очков F1DB нормализуется в 0; очки из классификации не пересчитываются. Для других сессий очки null. Статусы EX, DSQ, DNS, DNQ, DNP, DNF, NC нормализуются с сохранением исходного кода и причины. Неясный факт старта оставляется null. Точное время начала сессии не импортируется до подтверждения семантики часового пояса. Тренировки, отдельная стартовая решётка, пит-стопы, все индивидуальные быстрые круги, полная история до 2000 и дополнительные поля CSV пока не реализованы.
- Итоговые очки берутся из поэтапных снимков F1DB, сверяемых с сезонной таблицей F1DB; это внутренняя сверка источника, не независимая историческая проверка. Поправки не начисляются повторно, включая -10 McLaren 2000. Исторические причины решений и корректировки для расчётного ядра остаются отдельной задачей.
- 2017 R18: дублирующая позиция 19, Гасли без времени; числовая позиция и классификация неопределённы, исходный текст 19 сохранён, предупреждение в отчёте. Не присваивать 20 автоматически. Источник для проверки: https://www.fia.com/news/f1-vettel-takes-crucial-pole-mexico-ahead-verstappen-and-hamilton . Неоднозначные дубли с несколькими временами останавливают импорт.
- 2018: сезонная таблица содержит две записи Force India под одним ID, а последний поэтапный снимок только одну. Снимок сохраняется; обе версии таблицы находятся в отчёте standingConflicts. Нужна модель различения участника чемпионата и конструктора. Не публиковать как проверенные данные.

## Обязательное требование автоматического обновления (этап 03)
Новые сезоны и гран-при должны появляться без правок кода или ручного ввода года. На GitHub Actions — плановый запуск и ручной workflow_dispatch; обнаружение новых релизов F1DB, календаря и фактических результатов (Jolpica как дополнительный источник), скачивание во временный каталог, проверка хеша когда доступен, нормализация через тот же импортер. Переход года, будущий календарь, повторный импорт, изменения дат, отмена/перенумерация этапа, корректировки уже опубликованных результатов, неполный ответ, тайм-аут, конфликт идентификаторов и откат обязательны в тестах. Стабильные ID и пользовательский слой сохраняются. При неожиданном исчезновении этапа/сессии или ухудшении покрытия, конфликте или неуспешной проверке — блокировать публикацию, сохранить предыдущий проверенный набор. При успехе — атомарная публикация новой версии официального набора и журнал изменений, интерфейс автоматически получает доступные сезоны из данных. GitHub Actions и сетевой загрузчик в этой поставке ещё не реализованы. Не обещать обновление раньше появления данных у источника.
