# Модель данных 2.0.0 — проект контракта

Формат JSON Schema Draft 2020-12. Версия контракта 2.0.0 отличается от версии стартового комплекта 0.1.0. Источник истины для полей — schemas/*.schema.json. Поля обязательны, неизвестные значения явно null, ноль не заменяет неизвестное. Официальные данные и пользовательские данные валидируются отдельно.

| Сущность | Ключ | Смысл |
|---|---|---|
| sources | id | Поставщик, URL, дата получения, SHA-256 при наличии сохранённого ответа, ревизия |
| drivers | id | Пилот, полное имя, отдельные идентификаторы поставщиков (aliases) |
| constructors | id | Исторический конструктор, опциональная преемственность lineageId |
| circuits | id | Автодром |
| events | season + round | Гран-при, трасса, дата, статус |
| sessions | eventId + kind | Независимый статус и результаты каждой сессии |
| results | sessionId + driverId | Конструктор в данной сессии, классификация, очки, времена |
| standings | season + afterRound + kind | Опубликованные снимки личного и командного зачёта |
| adjustments | отдельные записи | Официальные штрафы/коррекции зачёта, не пользовательские правки |
| fastestLaps | sessionId | Лучший круг с источником |
| stints | sessionId + driverId + number | Шины и диапазон кругов включительно |
| predictions | sessionId | Упорядоченные идентификаторы прогнозируемых пилотов |
| overrides | sessionId + driverId | Локальная коррекция очков в альтернативном режиме |

## Идентификация

Первичный идентификатор пилота/конструктора/трассы создаётся на основе проверенного ID поставщика (`jolpica:hamilton` и т. п.). Он не меняется при добавлении новых источников. Alias сопоставляется по явному подтверждению, не по фамилии, номеру машины или индексу команды. Идентификаторы уникальны внутри соответствующей сущности. Номер этапа — текущий ключ календаря; при перенумерации требуется явная миграция ссылок пользователя, а не автоматическое переназначение. Идентификатор сессии образован из event ID и kind. Поля lineageId — группировка, не основание для объединения официальных очков. Справочник поколений команд и цвета по сезону запланированы дополнительно.

## Результаты и аналитика

- `position` — позиция из источника, `positionText` — исходное представление. `started`, `classified` — отдельные признаки, неизвестное null. Retired может быть классифицированным и иметь очки. Не пересчитывать официальные очки из позиции. Дробные очки сохраняются. Для квалификации/практики/grid points=null. Время в миллисекундах; исходный статус не выбрасывается.
- `final` означает окончательную классификацию по имеющемуся источнику, а не окончательность навсегда; `provisional` — предварительная, `partial` — неполная, `pending_results` — ожидаются, `unavailable` — источник не предоставляет данные, `scheduled` — запланирована, `cancelled` — отменена.
- `standings` — независимые официальные снимки, а не копия вычисленного зачёта. Поправки должны учитываться только один раз: если источник уже включил поправку в снимок, второй раз её не прибавлять. В 01.3/02 согласовать правила сверки и обработки командных штрафов, равенства очков и исключений. Сумма очков пилотов не всегда равна Кубку конструкторов.
- Сезон — логическая группировка по полю season, отдельный справочник пока не нужен. Пока один JSON-контейнер, позднее разбиение по сезонам без смены идентификаторов. Массивы stints/fastestLaps необязательны по наполнению; пустой массив означает отсутствие записи, не отсутствие факта. Детальная телеметрия и пит-стопы будут отдельными контрактами, не загружаем их при старте сайта.
- Расширение до 1950 предусмотрено диапазоном года, но особенности ранних сезонов (общие машины, дробление очков, зачёт лучших результатов, Indy 500 и особенности составов) потребуют дополнительных решений. Это не обещание полной совместимости с ранними правилами без изменения контракта.

## Миграция legacy → v2

| Legacy | Действие |
|---|---|
| gps.id / y / r / n / d / sp | Сопоставить календарь по проверенным году, этапу, дате, трассе; не доверять старому ID |
| drv.id / n / s | Хранить как свидетельство; восстановить по ID API, периоды по годам не угадывать |
| teams / at | Заново загрузить исторических конструкторов по каждой сессии |
| race / spr / q | Повторный импорт; не удалять дубли вручную, позиции уже повреждены |
| st / stSpr | Перечитать статус и классификацию из источника |
| fl / tyres | Перенос только после проверки связи пилота и сессии; исходное остаётся в backup |
| pred / ov | Карантин private/legacy-user-data.json, затем подтверждённое сопоставление; никогда не применять к официальному слою |
| year / meta | Настройки пользователя и происхождение исходной копии |

## Контракт будущего импортера

Загружать все страницы ответа поставщика, сохранять происхождение, применять лимиты/тайм-ауты, нормализовать во временный файл, валидировать, сверять с независимыми опубликованными зачётами, только потом атомарно заменить официальные данные. Сбой не изменяет рабочую базу. Не заменять ранее заполненную сессию пустым ответом без явной причины. Личные данные не входят в транзакцию импорта. Для неоднозначностей — отчёт и ручное решение. Повторный импорт того же источника не создаёт дублей. В 01.3 выбрать текущие поддерживаемые endpoints и проверить доступность, пагинацию, лицензии и фактическое покрытие Jolpica/OpenF1/FIA/Formula1.com.
