## Scope

The workflow `.github/workflows/f1-draft-update.yml` runs on pushes to `feature/f1-002-historical-import`. Manual dispatch and a twice-daily schedule (05:23 and 17:23 UTC) are configured for later use. GitHub requires the workflow on the default branch for schedule/manual dispatch; do **not** merge into main now. A feature-branch push is the initial cloud smoke test. Re-run jobs from the existing Actions run if needed. Schedule is not guaranteed to start at the exact minute. See https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows and https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow.

The runner has `contents: read`, no write/deploy permission, no custom secrets, no persisted checkout credentials; actions are pinned to reviewed upstream release commits (checkout v6.0.2, upload-artifact v7.0.1). Concurrent runs in the same ref are serialized (GitHub may replace an older pending run). Ubuntu 24.04 hosted image, Python venv and existing requirements, Node test runner. Local private files are not checked out. Tests requiring local backup / Jolpica / F1DB fixtures will skip on a clean runner; real archive rehearsal is a separate gate.

`tools/cloud_update.py` reconstructs the immutable initial reference from F1DB v2026.21.0, validated size, SHA-256, fixed reference observation date 2026-11-27, and expected sporting fingerprint. This is a fixed *starting reference*, not a cap on seasons or the latest source. Any deliberate change to historical normalization may require reviewed reference fingerprint revision. Then `prepare_update` fetches latest stable release, imports all available seasons (from 2000, no upper year), audits and checks compatibility. `Managed` initializes an isolated scratch site and rehearses activation (or no_change). It blocks newly introduced countback cases, checks the before/after hashes, and verifies the reference file is unchanged. The only outputs shared by Actions are whitelisted diagnostic JSON files and (after success) a DRAFT candidate. Retention 14 days. Artifacts may be accessible to authorized readers of the repository (including signed-in users for a public repository); they contain official-source data/reports, not private user predictions, not backups, and are not a deployment. CC BY 4.0 F1DB attribution remains in dataset provenance; independent verification and full public distribution/attribution review remain pending.

Every run starts from the same initial reference. No last-known-good state is persisted between runs and no prior artifact is implicitly trusted or activated. A changed calendar/result in a later release is checked against the initial reference, not previous cloud artifacts. A production state/promotion gate must be implemented before enabling scheduled publication. The real user's local preview and browser storage are untouched. No changes to main, GitHub Pages or legacy site.

Use a fresh output directory each time. The seed option uses the local known ZIP but the latest release is still fetched live. Omit it to test the same download path as GitHub Actions. If the archive and sporting state are unchanged as of the comparison date, expect `CLOUD DRAFT READY: v2026.21.0 no_change`; later status transitions (e.g. scheduled -> pending/unknown) or new sports data can result in `committed` in the disposable site only.
